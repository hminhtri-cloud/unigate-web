# Automatic admission news

`#/news` displays official Ministry and university/college links. Data lives in
`data/admission-news.json`; `data/admission-news.mjs` adapts it for React.
No AI API key or database credential is required.

The Ministry website timed out from GitHub-hosted runners during live tests.
The workflow therefore sets `NEWS_MOET_RELAY=true` to read those public pages
through UniGate's Vercel `/api/news-source` endpoint. The dedicated function is
configured in Singapore (`sin1`) close to the source; the application's other
functions keep their existing region. The endpoint only
allows the two Ministry listing paths and their official article URLs, verifies
redirects/TLS, limits response size/time, returns JSON (never executable HTML),
and caches successful responses for 30 minutes. It never touches MySQL or forwards
credentials. The collector still validates the original source URL, title, date
and content, and keeps direct HTTP/browser fallback if the relay fails. All other
sources are read directly. Local collection defaults to direct access.

## Run locally

```sh
npm ci
npx playwright install chromium
npm run news:check
# Report only; no data changes, commits or pushes:
npm run news:collect -- --sources MOET,UIT,TDTU,UTC2 --lookback-days 400
# Write validated data locally:
npm run news:update -- --sources MOET,UIT,TDTU,UTC2 --lookback-days 400
node --test tests/news.test.mjs
npm run build
```

Omit `--sources` to try all 100 configured sources: Ministry + 99 schools/campuses.
Only explicit official catalogue/profile hosts are trusted. A configured source
is not a claim that every article on it can be extracted. Some sources require
additional adapters or block automated visits. See the per-source report.

Default lookback is 60 days, overlapping across daily runs; publication year and
admission year are distinct. Change the target `admissionYear` in the JSON for a
new season. Limits: 12 candidate articles/source (configurable 1–40), 3 concurrent
sources, 90-second source and 25-minute total budgets. Deep or unusually busy
archives may require a larger candidate limit or additional configured entries.

## Verification and output

- Require official final URL, headline, article body and explicit publication date.
- Follow only allowlisted redirects/canonical links. Reject homepages, external
  canonical hosts, invalid/future dates, other admission cycles and missing facts.
- Never infer publication date from filenames, current-date widgets or related
  stories. No CAPTCHA bypass or disabled certificate verification.
- Excerpts are copied from source text, labelled as such, never generated by AI.
  Eight existing editorial summaries retain their review and are not overwritten.
- Deduplicate canonical URL, source/title/date, and content fingerprint. Preserve
  discovery time and ID when an automatically collected article changes.
- Rules determine relevance, category and draft status; this is not semantic AI
  verification and may miss unusual wording. Read the original for full conditions.
- Scope is prospective THPT students: exclude postgraduate/specialist, second-degree,
  distance, working-adult and secondary-vocational notices, scholarship payment
  lists for existing students, and multi-year archive indexes. Previously automatic
  items that now fail these scope rules are removed and counted in the report;
  source outages never remove articles and editorial records are preserved.
- Preserve previous data if a source fails; atomically replace JSON after validation.
- `artifacts/news/` contains `report.json`, `summary.md`, `proposed-news.json`.
  Reports distinguish zero matches, parse skips, network failures and time budgets.
  They are ignored by Git. A dry run still saves the proposed document for review.

## GitHub Actions and Vercel

`.github/workflows/admission-news.yml` schedules collection around **07:17 Vietnam**
daily. GitHub scheduling can be delayed; inactive public repositories can have
schedules disabled. The default branch must contain the workflow.

**Run workflow** defaults to `publish=false`: collect, test, validate, build and
upload reports only. `publish=true` allows publication. Publication is restricted
to `hminhtri-cloud/unigate-web`, the repository confirmed by existing Vercel commit
statuses. The workflow stages **only** `data/admission-news.json`; no changes means
no commit or deployment. Concurrent human pushes cause a normal push failure,
never a force push. A later run can retry.

`GITHUB_TOKEN` needs `contents:write`, subject to branch/organization policies.
Commits made with it do not start further GitHub workflows, so this workflow
performs its own validation/build. Vercel Git integration must actually accept
the bot commit. The workflow waits up to 7.5 minutes for its Vercel commit status;
a missing/failed deployment fails the job even if the Git push succeeded.

If required, create a deploy hook for the correct Vercel project/branch and save
it as the repository secret `NEWS_VERCEL_DEPLOY_HOOK`. Leave it unset when Git
integration works, to avoid a duplicate deployment request. Never store the URL
in source control. The optional hook still requires end-to-end verification.

Reports/proposed data are uploaded even on failure and retained 30 days. Review
Actions Summary and GitHub failure notifications (according to account settings).
There is no separate email/chat alert integration.

## Activation check

1. Run report-only on GitHub; inspect the artifact and per-source errors.
2. Run publication; check the resulting commit status and production news page.
3. Repeat: the same articles must not create duplicates or an unnecessary commit.
4. Confirm the daily schedule is active. Local files alone do not activate it.
